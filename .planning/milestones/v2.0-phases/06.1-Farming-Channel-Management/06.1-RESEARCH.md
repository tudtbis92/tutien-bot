# Phase 06.1: Farming Channel Management - Research

**Researched:** 2024-06-04
**Domain:** Discord Bot Infrastructure / Self-Bot Automation
**Confidence:** HIGH

## Summary

This phase focuses on automating the creation and assignment of private Discord channels within a dedicated `auth_server` for users utilizing the farming service. This ensures isolation between farming accounts and prevents `owo` bot responses from cluttering public channels.

The primary mechanism involves the main bot (using `discord.js` v14) creating a private text channel whenever a user sets up or updates their farming token. The `channelId` is stored in the `farming_accounts` table within the `settings` JSONB field. The `SelfBotWorker` (using `discord.js-selfbot-v13`) then consumes this `channelId` to target its automated commands.

**Primary recommendation:** Implement a `ChannelService` that uses `client.shard.broadcastEval` to manage channels across the sharded environment, ensuring the `auth_server` is found regardless of which shard it resides on.

### Pattern 1: Cross-Shard Channel Creation
Since the `auth_server` may reside on a different shard than the one receiving the `/farming` command, `broadcastEval` is required.

```typescript
// Source: https://discordjs.guide/sharding/additional-information.html#broadcasteval
const result = await client.shard.broadcastEval(async (c, { guildId, name, categoryId, overwrites }) => {
  const guild = c.guilds.cache.get(guildId);
  if (!guild) return null;
  
  const channel = await guild.channels.create({
    name,
    type: 0, // GuildText
    parent: categoryId,
    permissionOverwrites: overwrites
  });
  return channel.id;
}, { context: { guildId, name, categoryId, overwrites } });

const channelId = result.find(id => id !== null);
```

### Anti-Patterns to Avoid
- **Hard-coding Server IDs:** Always use `config.ts` or environment variables for `AUTH_SERVER_ID` and `FARMING_CATEGORY_ID`.
- **Sync DB/Channel:** Ensure the channel is created *successfully* before updating the DB to 'active' status.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| User ID Extraction | Custom Regex | `Buffer.from(token.split('.')[0], 'base64').toString()` | The first part of a Discord token is reliably the Base64-encoded User ID. |
| Permission Constants | String literals | `PermissionFlagsBits` | v14 uses bitwise flags for type safety and forward compatibility. |

## Common Pitfalls

### Pitfall 1: Worker "Stale Settings"
**What goes wrong:** `SelfBotMaster` currently only sends `START_BOTS` to workers. If a bot is already running, the worker ignores the new payload, meaning updated `channelId` or `settings` are never applied.
**How to avoid:** Update `WorkerManager.startBots` in `selfBotWorker.ts` to check if settings have changed and re-initialize the `FarmingLoop` if necessary.

### Pitfall 2: Channel Limit (500)
**What goes wrong:** A single Discord server can only hold 500 channels.
**Why it happens:** Growing user base exceeds the "auth_server" capacity.
**Warning signs:** `DiscordAPIError[50024]: Cannot create any more channels in this guild`.
**Strategy:** For this phase, assume 500 is sufficient, but log a warning when the count approaches 450.

### Pitfall 3: Self-Bot Server Membership
**What goes wrong:** Even if permissions are set, the self-bot cannot see the channel if it isn't a member of the `auth_server`.
**How to avoid:** Provide a persistent invite link to the `auth_server` in the `/farming setup` response or DM.

## Code Examples

### Extracting Self-Bot ID from Token
```typescript
function getUserIdFromToken(token: string): string {
  try {
    return Buffer.from(token.split('.')[0], 'base64').toString();
  } catch {
    throw new Error('Invalid token format');
  }
}
```

### Permission Overwrites for Isolation
```typescript
const { PermissionFlagsBits } = require('discord.js');

const overwrites = [
  {
    id: guildId, // @everyone role ID is the guild ID
    deny: [PermissionFlagsBits.ViewChannel],
  },
  {
    id: mainBotId,
    allow: [PermissionFlagsBits.ViewChannel, PermissionFlagsBits.SendMessages],
  },
  {
    id: ownerDiscordId,
    allow: [PermissionFlagsBits.ViewChannel, PermissionFlagsBits.ReadMessageHistory],
  },
  {
    id: selfBotId, // Extracted from token
    allow: [PermissionFlagsBits.ViewChannel, PermissionFlagsBits.SendMessages],
  }
];
```
