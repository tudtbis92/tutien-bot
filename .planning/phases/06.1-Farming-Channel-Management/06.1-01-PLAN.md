<task type="auto">
  <name>Task 2: Channel Management Service & Command Integration</name>
  <files>src/services/farming/channelService.ts, src/commands/game/farming.ts</files>
  <action>
    1. Create `src/services/farming/channelService.ts` implementing sharded channel operations (D-04):
       - `getUserIdFromToken(token: string)`: Safely decode first segment to string and validate as a snowflake (`/^\d{17,20}$/`).
       - `createFarmingChannel(client: Client, ownerId: string, token: string)`:
         - Extract `selfBotId` from token.
         - Call `client.shard.broadcastEval` with string-serialized permission bitmasks to prevent BigInt serialization errors:
           - Main Bot: View, Send, Manage (`"3088"`)
           - User Owner: View, Read History (`"66560"`)
           - Self-Bot: View, Send (`"3072"`)
           - Everyone: Deny View (`"1024"`)
         - Add guild channel limit checks (warn at 450, error at 495) to prevent API failures.
       - `deleteFarmingChannel(client: Client, channelId: string)`: Deletes the channel via `broadcastEval` (D-06).
    2. Update `src/commands/game/farming.ts`:
       - Add a `/farming stop` subcommand.
       - In `handleFarmingTokenModal`, check if the user already has a `channelId` in the DB. If so, call `ChannelService.deleteFarmingChannel` to delete the old channel before creating the new one (avoids permission leaks on token updates).
       - Store the new `channelId` in the `channel_id` column of `farming_accounts` (D-01).
       - In `/farming stop`, delete the farming channel, set the status to `stopped` in the DB, and notify the master via IPC to shut down the self-bot worker instance.
  </action>
  <verify>
    <automated>npm test src/services/farming/__tests__/channelService.test.ts</automated>
  </verify>
  <done>ChannelService implemented, token updates secured, stop subcommand added, and wired with mandatory cleanup.</done>
