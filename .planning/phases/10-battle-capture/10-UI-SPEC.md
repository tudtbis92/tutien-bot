# Phase 10 — UI Design Contract: Battle & Capture

> Visual and interaction contract for the Phase 10 frontend surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Medium note:** The Phase 10 "frontend" is the **Discord embed + message-component surface** (discord.js 14.26.2). There is NO web frontend, NO React/Next.js/Vite, NO shadcn. This contract adapts the web-oriented template to Discord-native budgets (character limits, ActionRow slot counts, button/select constraints). Where the template asks for px values, the answer is "client-controlled — the contract constrains what the bot CAN control."

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual discord.js embed/component builders — no shadcn, no web stack) |
| Preset | not applicable |
| Component library | none (Discord-native: `EmbedBuilder`, `ButtonBuilder`, `StringSelectMenuBuilder`) |
| Icon library | `src/ui/theme.ts` `EMOJI` constants (unicode) + `heroEmoji()` animated custom emoji (`<a:name:id>`, D-21) |
| Font | Discord client font (gg sans) — NOT controllable; contract constrains character budgets instead |
| Theme source | `src/ui/theme.ts` — **ALL embed colors MUST come from `COLORS`; never hardcode hex** (established Phase 8/9 rule) |
| Embed contract | Every embed: `.setFooter(embedFooter(shardId))` + `.setTimestamp()`; title starts with a leading emoji (established convention: "⚔️ Kỳ ngộ", "🧭 Hành trình bắt đầu", "👑 Boss thường xuất hiện!") |
| Localization | All UI strings via i18next `sanguo:` namespace (VI/EN/ZH-CN, zero-hardcoded lint); hero/zone names from DB per-locale columns (D-07) — never i18n keys |
| Hidden mechanics | D-12 hard rule: IV numbers (0–31) and rarity (1–5) are **never rendered**. Only the IV grade and the single displayed capture % appear. (see Never-Render list below) |

Sources: `src/ui/theme.ts`, `src/ui/embeds/*` (Phase 9 builders), `locales/vi/sanguo.json`, CONTEXT.md D-12/D-21, STATE.md CR-09-01..06.

## Spacing & Layout Budgets (Discord-native)

Web pixel spacing does NOT apply — the Discord client renders layout (padding, gaps, embed chrome). The contract constrains what the bot controls. **All budgets below are hard Discord API limits unless marked (contract):**

| Token | Value | Usage / Constraint |
|-------|-------|--------------------|
| ActionRow slots | ≤ 5 components/row, ≤ 5 rows/message | Buttons per capture view = 4 max in ONE row (3 tier + 1 retreat); retry replaces the row content, never adds a 5th |
| Select+button rows | 1 row each | CR-09-01 (live-verified): a select menu and buttons MUST be in separate ActionRows (`COMPONENT_LAYOUT_WIDTH_EXCEEDED`) |
| Embed fields | ≤ 25 per embed | Battle log uses description, not fields (D-07 single embed); collection uses ≤ 2 fields (title/count + lines) |
| Battle log rounds | ≤ 20 (contract, D-05 agent range) | Bounds the description; each turn = 1 line ≤ ~80 chars → log ≤ ~1,700 chars, safely under 4,096 |
| Edit-reply components | `components: []` on every `editReply` | CR-09-03 (live-verified PATCH merge semantics — stale components persist otherwise) |
| embedFooter | always appended | `Tu Tiên Bot • Shard {id}` — every embed |

Exceptions: none — all Phase 10 surfaces sit inside these budgets by construction.

## Typography (Discord client-controlled)

Font, size, weight, and line-height are **not controllable** — Discord renders gg sans at client scale. The contract therefore fixes **character budgets** and **markdown emphasis rules** (the only typographic controls the bot has):

| Role | Budget | Markdown rule |
|------|--------|---------------|
| Embed title | ≤ 256 chars | Leading emoji + short noun phrase (convention); bold never in titles |
| Field name | ≤ 256 chars | Short label, no emoji (emoji lives in value or title) |
| Field value | ≤ 1,024 chars | Line-per-hero list; numbers in `**bold**` |
| Embed description | ≤ 4,096 chars | Battle log (turn lines), capture chance line, empty-state body |
| Button label | ≤ 80 chars | Verb-first CTA: "Chiến đấu", "Bắt lại", "Chọn {{name}}" |
| Select option label | ≤ 100 chars | Zone name (per-locale DB, D-07); emoji via `option.setEmoji` NEVER in label (CR-09-02) |
| Select option description | ≤ 100 chars | Optional zone hero count |
| Emphasis | `**bold**` only | Numbers, hero names, CTA words. Never `*italic*`, never `__underline__` in sanguo embeds |
| Zone headers (map content) | `# ` H1 prefix | D-22 (live-verified): emoji-render-large headers ONLY in message content, never in embeds |

## Color

All values from `src/ui/theme.ts` — extend nothing; reuse the existing keys.

| Role | Key / Hex | Usage in Phase 10 |
|------|-----------|-------------------|
| Dominant — sanguo journey | SEASON `0x8B5CF6` | Travel, encounter (non-boss), battle log, capture view, heroes collection, starter picker, hero detail — every sanguo surface by default |
| Secondary — main game | PRIMARY `0x6B46C1` | NOT used in sanguo (reserved for main-game profile/info embeds) — do not introduce |
| Accent — boss | GOLD `0xF59E0B` | Boss thường encounter variant + boss capture view ONLY (D-13; live-verified Phase 9 UAT "GOLD 0xF59E0B") |
| Accent — success | SUCCESS `0x10B981` | Capture success, battle win, starter acquired |
| Accent — failure | DANGER `0xEF4444` | Capture fail + flee, battle loss, insufficient-fee error, fainted-block error |
| Accent — caution | WARNING `0xF59E0B` | Capture fail WITH retry still available (setback, not loss); soft-lock warnings (all heroes fainted) |
| Neutral | NEUTRAL `0x6B7280` | Spar (practice) embeds — no stakes, no reward, no HP loss (D-17) |

**Accent reserved for (10%):** boss variant (GOLD), capture/battle outcome states (SUCCESS/DANGER/WARNING), spar (NEUTRAL). Accent colors are **never** used on journey/summary surfaces (SEASON covers them). Fee amounts render as `💎` + bold number in the button label — a price, not a color accent.

**Never-render contract (D-12, hard):** IV stat numbers, IV sum, rarity number, capture formula, flee %, pity count/increment, tier multipliers, base stats. Only the IV grade (Hoàng Kim / Hồng ngọc / Lam cấp / Lục cấp / Hôi cấp — existing grade keys, STATE D-12) and the single capture % may appear.

Sources: `src/ui/theme.ts`; STATE.md D-12/D-13 + Phase 9 UAT GOLD confirmation; CONTEXT.md D-12.

Stars never derive from rarity at render time — the two columns are seeded separately so rarity stays invisible. Planner/executor: confirm the public column in the D-02 content research.

**Dismissed (probe over-classification, reason required):**
- battle-log: empty / partial / zero-one-many — log renders only while a battle runs; no empty/partial log exists by construction; zero-one-many covered by the round cap.
- capture-view: empty / partial — a capture view always has a pending encounter + server-validated fee state; no empty/partial capture by construction (no-pending-encounter is the `battle.no_encounter` error case, already covered).
- hero-detail: empty / loading / partial / overflow / zero-one-many — single-hero fixed-field surface; unknown hero → `hero.error` (covered); no loading skeleton on Discord; fixed fields bound all length states.
- starter-picker: loading / error / populated / partial / overflow / zero-one-many — renders only when collection is empty with exactly 3 pre-fetched buttons; errors covered by `heroes.error`; fixed 3-option construction bounds the rest.
- encounter-entry: empty / loading / error / partial / overflow — server-produced embed, never empty/partial when shown (absence surfaces on the action path, not the surface); loading = deferReply; overflow bounded by field/description budgets.
