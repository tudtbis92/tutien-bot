# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This phase ships a **Discord bot** UI, not a web frontend. The "UI surface" is Discord embeds, typed emoji registries, and i18n copy. Pixel-level spacing/typography are controlled by the Discord client and are declared N/A below with the bot-controllable structural contract in their place. **No shadcn gate applies** (tech stack is Node.js + discord.js, not React/Next/Vite) and **no registry safety gate applies** (no component registries).

## Spacing Scale

**Pixel scale: N/A — the Discord client owns the canvas.** The bot's only "spacing" lever is embed structure. Declared structural scale (source: `buildProfileEmbed.ts` conventions):

| Token | Value | Usage |
|-------|-------|-------|
| field-inline | 3 per row | `inline: true` field groups — maximum 3 columns per row (Discord limit) |
| field-separator | `\u200b` | zero-width blank inline cell for row alignment (pattern at `buildProfileEmbed.ts:72`) |
| field-prefix | `{EMOJI} {label}` | emoji-prefixed field names — existing convention, do not deviate |
| field-value-max | 1024 chars | per Discord embed field limit |
| fields-max | 25 | per Discord embed limit |
| embed-footer | `embedFooter(shardId)` | every embed; `.setTimestamp()` on all state-bearing embeds |

Exceptions: none. `/sanguo map` scaffold must stay well under limits (5–10 placeholder nodes → ~1–3 fields).

## Typography

**Bot-controlled typography: N/A — Discord renders all text.** The bot controls only *content* and *structure role*. Declared role mapping (executor contract):

| Role | Discord rendering (reference) | Bot contract |
|------|------------------------------|--------------|
| Title | client bold ≈16px | `.setTitle(t('sanguo:map.title'))` — localized, never raw string |
| Field name | client semibold ≈14px | emoji-prefixed localized label (field-prefix token) |
| Field value | client regular ≈14px | localized content; content names from DB per-locale columns (D-07) |
| Description | client regular ≈14px | localized; used for empty/error body copy |
| Footer | client small | `embedFooter(shardId)` — shard debug info only |

No font sizes, weights, or line heights are settable — do not attempt. All user-facing text passes through `t()` (i18next) — zero hardcoded strings (I18N-03 enforcement).

## Phase-Specific Contract: Emoji Rendering (SC3)

- **`heroEmoji(heroId, tier?)` is the SOLE render point** for sanguo emoji (D-15). Default tier `t0`; `_star` variant supported. Direct emoji-ID embedding in command/event code is blocked by ESLint rule (mirrors Phase 1 `EMOJI` pattern).
- **Missing emoji key → fallback to tier-default (`t0`) emoji; never an empty string; never a raw `<:name:id>` literal.**
- **Startup check (D-14):** `applicationId === CLIENT_ID` compared at startup before `client.login()`; mismatch → fatal exit. Contract value: `CLIENT_ID` must equal `1381818375633899562` (D-16) or the generated registry is invalid.
- **Build-time generation only (D-13):** `scripts/gen-sanguo-emojis.ts` reads `emojis.json` from the sibling repo at dev/build time and emits committed `src/assets/sanguoEmojis.ts`. Runtime NEVER reads the sibling repo.

## Phase-Specific Contract: Interaction (SC3)

- Command registration: `/sanguo map` drops into `src/commands/` (commandLoader autodiscovery), no subcommands in Phase 8.
- Response: non-ephemeral embed (public map info — other players may view).
- No message components (buttons/selects) in Phase 8 — the map scaffold is read-only; travel-cancel etc. arrive in Phase 9.
